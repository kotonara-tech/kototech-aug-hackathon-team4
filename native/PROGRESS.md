### ビルド・テスト環境の調査（#13）
起票時の前提「解析が極端に遅い」「テストがランダムに落ちる」は**どちらも誤りだった**ことを計測で確認。詳細は `app/BUILD_NOTES.md`。

- `flutter analyze` の48分は**初回のみ**。2回目以降は10〜12秒
- `The Dart compiler exited unexpectedly` は**常に本物のコンパイルエラー**。並列実行時に無関係なファイルが巻き添えで失敗報告されるだけ
- 恒久的な設定変更（`dart_test.yaml`）は不要と判断し、見送った

### 配信準備（#23 / #24）
配布用APKをビルドし、手順を `app/DISTRIBUTION.md` にまとめた。`dist/` は `.gitignore` 済みで APK 自体はコミットしない。

- **USB接続は必須ではない**。APKファイルを端末に送って開くだけで入る（release は 17.5MB）。ログが必要なときはワイヤレスデバッグ（Android 11以降）でつなぐ
- 配布APKの署名証明書 SHA-1 が `DF:39:D5:02:...:2E:BB`（debug keystore）であることを `apksigner` で実測し、#11 に登録用の値としてコメント済み
- **ビルドマシンを固定する**前提を採用（#24）。別マシンでビルドすると SHA-1 が変わり、カメラも撮影も動くのに**サインインだけが失敗する**分かりにくい壊れ方をする

### Codexレビューで判明した実装の穴（2026-08-22）

実機検証の前に潰しておきたい3点。いずれもコードを読んで裏を取った。

| 箇所 | 問題 | issue |
|---|---|---|
| `lib/photo_source.dart:76` | 撮影画像を `getTemporaryDirectory()` へ保存している。OS のキャッシュ整理で消えうるため、履歴に「送信失敗」と出ていても**再送すべき実体が無い**状態が起こる | #32 |
| `lib/drive_uploader.dart:30` | フォルダIDのキャッシュキーが `'driveFolderId'` 固定でアカウントに紐付かない。403/404 でも破棄しないため、**アカウント変更・フォルダ削除後は失敗し続ける** | #33 |
| `lib/drive_uploader.dart:77` | `_ensureFolderId` に排他制御が無い。撮影完了時点で撮影中フラグを解放する設計（#17）のため送信は並行しうる。初回に2件が同時に走ると**フォルダを2つ作る** | #35 |

あわせて、**送信失敗した写真は自動再送されない**（#19 は future）。履歴に赤い「送信失敗」が出ても、停止→開始で再送は走らず新しい写真が増えるだけである。この仕様を `AGENTS.md` に明記し、エラー表示も例外文の生出力から利用者向けの案内に変える（#34）。

### #7 の扱いについて
`AGENTS.md` 3節では**スコープ外**として整理されているが、#6（スリープ抑止）を同じ理由でスコープ外から格上げした前例がある。#6 で「画面が消えて止まる」経路は塞いだものの、「ホームに戻る・着信で止まる」経路は塞げていない。デモ中にホームボタンを一度押すだけで無言のまま欠測するのは `risk-assessment.md` 反対2 そのものであり、**実装する方に倒したい**。ただし Codexレビューの結論に従い、優先度は P1 の後（P2）に置く。

### テスト件数について
`91件パス / 85.0%` は**実機検証の代わりにはならない**。上の3点はいずれもテストが通ったまま残っていた穴であり、`photo_source.dart` は 0%（プラットフォーム依存のため意図的）である。数字を達成度として読まないこと。

## 未解決の課題

- **Web連携の受け渡し方法が未合意**（#21 / **別トラック**）: `drive.file` スコープは**アプリが作成したファイルしか見えない**ため、「Driveに置けばWebから読める」とは限らない。ただし現行 MVP の DoD に Web連携は含まれないため、#11 を止めてまで先に決める必要はないと判断した。Webアプリ本体は別担当がリリースするため、ここでは実装しない
- **GCP側のOAuth設定が未着手**（#11 / DoD を直接ブロック）: 同意画面・Android用OAuthクライアントID発行。登録に必要な値（パッケージ名・SHA-1・スコープ）は issue にコメント済みで、あとは Console 上の操作のみ。**これが終わるまでサインインできず「開始」ボタンが押せない**ため、撮影の連続動作＝完了条件に到達できない
- **実機での動作確認が未実施**（#8）: APKと手順は揃っている。#11 完了前でもプレビューまでは確認できる
- **`flutter run` 環境が未整備**（#12）: `adb devices` は空。ブロッカーではない（APK配布で足りる）
- **レスポンシブ未対応**（#22）: 現状は縦積みレイアウトのみ。履歴一覧に固定高 180px を置いており端末サイズに追従しない。サイズ別のウィジェットテストが無く、**崩れても気付けない**
- **アプリ側に残る実装の穴**（#32-#35）: 保存先が一時領域 / フォルダIDキャッシュを破棄しない / 失敗時の案内が例外文の生出力 / フォルダ作成が競合しうる。詳細は「残件の整理」
- **未実装のSTEP**: #7（ライフサイクル対応）のみ
